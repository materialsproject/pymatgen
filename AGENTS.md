# CLAUDE.md — pymatgen (umbrella repo)

This is the umbrella `pymatgen` package. The foundational data structures live
in **pymatgen-core** (separate repo at `~/repos/pymatgen-core`, a dependency of
this one; it has its own `AGENTS.md`). Ecosystem docs are built from this repo
(`docs/`, Jekyll).

## Setup & commands

- `uv`-managed: `uv sync`, `uv run pytest tests`,
  `uv run ruff check . && uv run ruff format --check .`
- Release and changelog helpers are pyinvoke tasks in `tasks.py`
  (`update-changelog`, `make-doc`, `release`, `release-github`).
  Admin procedure: `ADMIN.md`.

## Changelog & releases

- The changelog is `docs/CHANGES.md`.
- "Update changelog" means: `uv run invoke update-changelog`, then **edit the
  autogenerated commit list for brevity** and attribute significant features to
  their developers. Releases here usually follow a `pymatgen-core` release —
  fold in or point to the corresponding entries from
  `~/repos/pymatgen-core/CHANGES.md` for that version.
- Full release: green CI → `uv run invoke update-changelog` +
  `uv run invoke make-doc` → `git add docs && git commit -m "Update changelog
  and docs"` → `uv run invoke release` (tags, pushes, creates the GitHub
  Release; CI publishes to PyPI, conda-forge follows).
- The package version derives from the git tag, so the tagged commit must have
  a **clean working tree**. Never tag a dirty tree; never delete or force-push
  tags.

## Docs

- Ecosystem documentation (including for pymatgen-core) lives here. When a
  change in pymatgen-core affects user-facing docs (e.g. installation of
  external tools like enumlib/Enumlib.jl), update the docs in this repo.
